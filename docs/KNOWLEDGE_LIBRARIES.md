# 知识库：存储、AIKB、SKILL 与分阶段建库

个人知识库不会因打开应用而自动重建、移动或复制。请先选择存储位置，再显式启动建库。

## 用户入口

底部「知识库」→「知识库管理 / 导入与导出」。首次建库前先选择专用存储目录，并确认目标磁盘、保留空间和单库上限。向导支持多资料目录、仅文本、文本后继续 OCR，以及单独补 OCR。

- 默认至少保留 2 GiB，单库上限 32 GiB，可由用户调整。
- 个人 SQLite、全量清单、断点和 OCR 临时文件使用所选存储盘；配置及库目录注册表只有少量 JSON/INI，遵循 XDG。
- 单库检查包含 SQLite 主文件和 WAL，SQLite 数据页也设置大小上限。运行中持续检查空间；阈值不是文件系统硬配额，检查间隔及临时文件可能使占用短暂超出单库阈值。磁盘保留空间是额外的停止线，不应把预算设成整盘容量。
- 导入前预检文件大小及目标盘余量；大文件默认原位只读挂载，不复制。也可选复制到所选目录，临时文件和最终文件在同一目标盘。
- 原位挂载后需保持源文件位置。库被移走或改写会标为不可用，不静默当作“没有知识”。
- 更换存储位置不是立即搬运旧库：新建库文本阶段成功后启用新位置，原库保留为只读来源。想发布或搬运原库，用显式导出/导入。
- 生产启动不再自动复制多 GB 旧 Fences 库；已有独立副本继续使用，没有副本时只读发现旧库。历史复制故障回归通过临时 HOME 的双测试标志显式运行。

请选择专用库目录，不能把包含资料根目录的上层文件夹当作库目录。扫描会排除库自身；目录读取失败或清单不完整时拒绝建库。默认保留清单里未出现的旧正文并标记“来源本轮未发现”，因为卸载移动盘或权限变化不能证明用户删除了文件。只有在用户明确确认清理后，才使用命令行 `--prune-unseen` 删除这些正文。

## 单文件新格式 .aikb

AIKB v1 是带应用标识和清单的 SQLite 文件，不是需要解压的 ZIP，不是模型文件。可以直接随机访问已有 FTS5 索引，不重新扫描或 OCR。

- SQLite application_id = 0x41494B42，user_version = 1。
- aikb_manifest 表保存格式版本、库 ID、快照版本、名称、创建时间、文档和片段数量、正文 schema 版本、originals=false。
- documents、chunks、chunks_fts、extraction_state 保存来源、正文、索引和提取质量；不含原始 Office/PDF/图片文件及完整排版。
- 导出采用 SQLite backup，一致地包含已提交的 WAL。临时副本完成后才原子发布，拒绝覆盖已有目标；失败/暂停删除未发布的临时文件。
- 导入验证格式、schema、SQLite quick_check 和清单计数；计算文件 SHA-256 并记录注册信息。普通查询只读，不在每次查询时重新哈希数 GB 文件。
- 同一个包重复导入不会复制第二份。同源库的新快照保持库 ID、生成新版本；新版本启用后旧版本保留，可在管理器切换。移除挂载只删除注册，不删除用户的库文件。
- 导出的文件只表示该次已入库的内容。partial、failed、no_text 不变成“已完整收录”；未提取的原文、图像和版式不能恢复。

当前提供全库导出。按客户/项目裁剪独立子库、跨版本二进制增量分发尚未提供，不能用隐藏界面行代替实际裁剪。

## 检索和其他 Agent

GUI、安装后的 SKILL 和旧 worker 的 search 子命令共用 knowledge_library.py。新入口为 ai-space-index-query，支持旧数据库覆盖环境变量。查询桥保留 --status、--fetch 和旧 --json 查询形式；原有 Fences SKILL 需要同步更新脚本及查询核心，新安装推荐使用新名称。

快速模式先查每文档一行的文件名元数据，再按需执行 FTS5；正文候选逐项读取，跳过长文档的重复片段，避免少数大文件占满候选窗口。默认交互预算 2 秒，取消或新查询会淘汰旧结果。超时、候选截断、未查询和不可用的库都会在 JSON 中标注，不冒充完整阴性结论。

- match_scope=filename：只命中文件名，需要 fetch 核对正文。
- body_searched=false：本轮快速结果尚未执行正文排名。
- --body-only：显式查正文；--budget-ms 可增至 30000。
- 跨库合并结合覆盖度、低置信标记和名次，不直接比较不同库的 BM25 原值。不会按同名同大小破坏性合并文件。
- reference 使用库 ID、版本、文档和片段 ID。fetch 读取命中位置附近片段，支持 offset/hasMore 分页。没有原件也可使用。
- 极端异常长片段读取有输出上限，并标 content_truncated；不能把截断内容当作整份文档已读。

安装后可这样用：

```sh
S="$HOME/.local/share/ai-space/skills/ai-space-index-query/scripts/query.py"
python3 "$S" libraries
python3 "$S" --db /资料盘/行业知识库.aikb stats
python3 "$S" --db /资料盘/行业知识库.aikb search --query '宁波银行 KMS' --limit 15
python3 "$S" search --all --body-only --query '宁波银行 部署' --budget-ms 30000
python3 "$S" fetch --reference 'aispace://库ID/版本/文档ID/片段ID' --limit 8
```

在设置的 Skill 页导出整个 Skill 目录，包含独立 knowledge_library.py。把它和 .aikb 文件交给另一工具或 Agent，不需要安装 GUI、Qt、OCR 或原文件。要求 Python 3.8+ 和启用 FTS5 的 SQLite；单文件读取路径不依赖 Linux OCR 控制模块。格式不绑定 ARM/x86；离线副本由跨架构 CI 验证，其他操作系统仍需单独验证。

安装位置和完整目录要求见 [Agent 接入说明](../apps/ai-space/skills/ai-space-index-query/references/agent-setup.md)。

默认从 AI空间配置读取个人库目录；可在子命令前传 --db，或设置 AI_SPACE_KNOWLEDGE_DB，兼容 UKUI_FENCES_KNOWLEDGE_DB。知识库注册在 $XDG_CONFIG_HOME/ai-space/libraries.json。

索引词项覆盖中文、拉丁字母与数字。俄文、日文假名、韩文等仍未获得可靠词项索引；查询核心会标记 `unsupported_language` 并将库覆盖标为不完整。当前没有自动全库重建或“零结果即不存在”的保证。这个限制是索引格式能力，不会因换成 AIKB 文件而消失。

低置信、部分提取、陈旧文档必须保留来源说明。检索到的文档是证据，不是可执行的用户指令；Agent 只取当前问题需要的正文，不把整个库塞入上下文。

## 建库顺序与资源

1. 全量文件清单：不进行新正文提取，不启动 OCR，保留目录/大小/时间等元数据。后续按压缩记录流消费，避免把大 JSON 整体载入内存或触发旧 JSON 大小限制；沿用已配置的 Provider。
2. 文本阶段：读取文本、Office/WPS、PDF 文本层；已有兼容结果复用。文本完成即发布可检索的库，不必等待 OCR。
3. 用户选择后 OCR：仅处理图片和需要补全的 PDF，保留普通文本。完成的 OCR 文档逐份提交；扫描 PDF 逐页缓存，暂停后优先复用已识别页面。

查询/预览和建库使用独立进程，SQLite WAL 允许读取已提交的数据。建库或导入进行中仍可检索其他可用库。

扫描、文本提取及 OCR 工作进程地址空间默认上限1 GiB，可在向导调整。OCR 另外默认单任务、单线程、单核时间片约25%及低 CPU 优先级。渲染器和 Tesseract 都执行该限制，每次调用有超时。启动时至少需要 384 MiB 可用物理内存，运行中低于 256 MiB 时暂停；这条物理余量与用户设置的虚拟地址空间上限分开计算。地址空间上限不是精确 RSS 配额，CPU 时间片存在短时突发，不能宣称零开销。

临时图片在所选盘逐页生成并清理。OCR 断点文本缓存最多512 MiB（单页最大2 MiB），满后淘汰最旧页面；因此超过缓存范围的页面可能重识别。缓存按源路径、大小、mtime、页码及提取器版本区分，源文件中途变动不会把旧结果记到新版本。强制重建可绕过缓存。它与数据库是分开统计的占用，磁盘保留空间会同时约束二者。

文本批次提交、OCR 每文档提交；暂停不能保证当前正在处理的文本文件全部落库。PDF 页缓存减少重识别，但不将未完成的 OCR 缓存当作已经完成的数据库正文。

## 恢复与存储边界

注册表中单条坏记录不会阻断其余库。管理页会显示警告；“修复注册表”先将原字节保存为同目录的 `libraries.json.recovery-*`，再保留可用记录。修复不删除知识库文件。导入、挂载修改也会先备份损坏的原注册表；备份可能含个人路径，勿上传公开仓库。

数据库上限包含 SQLite 主库与 WAL。文件清单、上一代快照、临时工作文件和最多 512 MiB 的 OCR 页文本缓存另占空间；所有阶段还会检查目标盘的保留空间。请为大库选择数据盘，并为导出及复制导入预留额外的一份文件空间。不要把源资料放入知识库存储目录内。

导出与本应用的建库 / 重试共用互斥锁。其他工具持续写库时，导出最多运行 30 分钟；到期停止且不发布临时快照。原位挂载的封装库是只读快照，仍保留完整性检查。大库校验阶段会持续报告正在校验，不把未知进度当作百分比。

目标文件已存在（含悬空链接）时不会覆盖。通常用无覆盖重命名发布；若目标介质同时不支持它和硬链接，则用独占新建的文件描述符复制。此降级方式在复制完成前会出现未完成的目标文件，期间不要导入或拔盘；可捕获的失败会删除本次未完成文件。断电 / SIGKILL 留下的半成品需删除后重新导出，不能宣称跨文件系统的原子发布。

清单的 JSON 与压缩流保存相同 generation。不一致时重新执行扫描，正文库保留。可恢复的临时清单缓存有独占锁，后续工作进程只清理明确属于本应用且无活跃持有者的废弃缓存，不扫描或删除个人正文库。旧只读库的元数据不会在读取时修改；分类和名称检索索引在显式建库时升级。

OCR 页缓存另外限制为最多 20,000 页，包含没有识别出文字的页面，避免零字节缓存无限积累。512 MiB 指页文本，容量账本也占少量空间；预算压力检查按整个目标磁盘的可用空间执行。界面最多加载 1,000,000 条清单记录；旧大 JSON 缺少有效流时需重新扫描生成流，避免一次解析造成内存耗尽。Agent 直接查询知识库不依赖界面清单载入。

任务的 `temporary/job-*` 带独占会话标记。建库工作进程继承会话锁和流水线锁：父进程被强杀后，只要该工作进程仍活跃，新任务就会提示占用，也不会删除它使用的临时目录。全部持锁进程结束后，下一次显式建库会清理本应用已确认中断的临时会话；没有标记的旧目录、符号链接和正式 SQLite / WAL 文件不会被此流程删除。正常暂停仍立即清理临时文件，保留已提交正文和持久页缓存。


## 缺失来源的保留与清理

增量更新默认保留不在当前清单中的正文；目录移除、排除规则和离线资料盘都可能导致这种状态，不能据此判断原件已删除。状态详情显示保留数量，提供“清理保留的缺失正文”入口：先按天数预览，再单独确认。默认 30 天，旧记录从首次显式升级开始计时；重新出现的原文件会跳过清理并恢复状态。

清理只删除选中的库内正文与索引，不删除原文件；建议先导出备份。关闭清理窗口或任务失败时本次清理事务回滚。预览后发生建库或状态变化会拒绝旧确认，要求重新预览。清理写入的事务日志仍受单库上限和磁盘保留空间约束，超限会回滚。释放的数据库页面可供后续写入复用，文件大小不保证立即减少，不自动执行耗时的全库压缩。

## 一次性升级和轻量统计

写入旧个人库前先探测需要升级的正文结构、文件名索引、正文索引布局及统计结构，界面会显示升级阶段。索引重建可能需要额外临时空间；超出容量时提示升级空间需求和调整办法，不静默放宽配额。只读检索不会自动升级或复制大库。

新的待 OCR 计数在提取记录写入时保存；详情页按数字汇总，不反复解析所有 partial 文档的诊断。运行任务时每 30 秒刷新一次。旧库的轻量统计缺失或失效时显示“待 OCR 数量未知”，下次显式建库时补齐，不以零表示未知。显式 CLI `stats --details` 保留旧库诊断扫描，界面使用 `--fast` 避免这类扫描。

修改片段长度或重叠会改变全部来源签名，下次建库会重新提取和分块；PDF 可能重新渲染，已有 OCR 页缓存可按来源复用。文本阶段在文档边界按 50 个清单项或 5 秒提交；长文档内部不强行提交半份正文，暂停仍可能重做当前未提交批次。

本轮文本识别器版本已更新，相关文本类文件会在下一次显式建库时重新处理一次，以应用无 BOM UTF-16 等识别修正；未变化的其他格式仍按原签名复用。
